## 作業する環境を選ぶ

一つのワークスペースに開発、ステージング、本番などの **環境** を作れます。
シークレットと出力先のファイルは環境ごとに管理します。

```sh
enbu switch -l
enbu switch -c staging
enbu pull
```

作成済みの環境に戻るときは `enbu switch staging` を使います。
切り替えた環境は端末ごとに記録されます。
チームの初期値は `enbu.toml` の `default_env` で指定します。

## .env とシークレットを更新する

`enbu pull` は出力ファイルにあるマーカーを使って enbu の管理領域を判定します。
マーカーより下にあるローカル変数のうち、enbu で管理していないものは保持します。
保持した変数はキー順に書き直され、コメントは引き継がれません。
共有側で削除された管理対象のキーは、次の同期で出力から取り除きます。
ファイル全体を置き換える場合は `enbu pull --replace` を使います。

値の登録には、非表示のプロンプト、標準入力、または `--value-file` を利用できます。
証明書のような複数行の値も扱えます。
コマンドの引数に値を直接書くと、シェル履歴や実行中のプロセス一覧に残ることがあります。

## CLI、デスクトップアプリ、VS Code を使う

CLI とデスクトップアプリは Windows、macOS、Linux に対応しています。
Linux のデスクトップアプリは GTK 4 と WebKitGTK 6.0 を使います。

VS Code 拡張機能では、デスクトップアプリと共通の画面から、ローカルで起動した enbu を操作します。
対象はローカルおよび WSL の信頼済みワークスペースです。
Remote SSH、Dev Containers、Codespaces、vscode.dev は対象外です。

WSL では鍵操作や認証トークンの管理を Windows 側の `enbu.exe` に委譲します。
ストレージへのアクセスや `.env` の操作は WSL 内で行います。
Windows 側と WSL 側で enbu のバージョンをそろえてください。

## FAQ

### .env を書き出さずにアプリケーションを起動できますか？

`enbu run -- npm start` のように実行すると、復号した値が子プロセスの環境変数に渡ります。

### enbu run を使うとログへの露出を防げますか？

非対話的な出力では、6 文字以上の既知のシークレットに一致する部分をマスクします。
Base64 や URL エンコードなどで変換された値は出力に残る可能性があります。

### オフラインでは何ができますか？

生成済みの `.env` は、保存先に接続できなくてもアプリケーションから読み取れます。
共有状態の取得や変更の公開には、保存先への接続が必要です。

### JSON で結果を受け取れますか？

対応するコマンドでは `--json` で構造化された結果を受け取れます。
`enbu pull --json` の出力には復号済みの値が含まれるため、ログに保存しないでください。

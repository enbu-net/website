## ストレージへのアクセス権と復号権限

チームの端末には、保存先を読み書きする権限と、enbu で復号する権限の両方が必要です。
GHCR へのアクセスには GitHub の認証を使います。
復号と変更への署名には、端末ごとの鍵である **Identity** を使います。
GitHub のトークンを取得しても、承認済みの端末の鍵がなければシークレットは復号できません。

GHCR で作られた非公開パッケージには、初期状態では作成者だけがアクセスできます。
参加するメンバーには、パッケージに参加要求を書き込める権限を付与してください。
リポジトリの権限を使う場合は、パッケージの設定でリポジトリを接続し、**Inherit access from repository** を有効にします。

## ワークスペースに参加する

1. 参加するメンバーは、共有された `enbu.toml` のあるフォルダで `enbu init` を実行します。enbu は参加要求を保存先に送り、端末のフィンガープリントを表示します。
2. メンバーは、参加要求とは別に、対面や普段使う連絡手段でフィンガープリントを管理者に伝えます。
3. 管理者は `enbu member approve` を実行し、表示されたフィンガープリントが本人から受け取ったものと一致することを確認して承認します。
4. 承認が完了すると、参加した端末でも各環境の現在のシークレットを復号できます。参加したメンバーは `enbu pull` を実行します。

## 管理者とメンバーの役割

| 操作 | Member | Admin |
| --- | --- | --- |
| シークレットの読み取りと変更 | 可 | 可 |
| 端末の承認と削除 | 不可 | 可 |
| 管理者権限の付与と取り消し | 不可 | 可 |
| 履歴の整理と保存先の移行 | 不可 | 可 |

最初にワークスペースを作った端末は Admin になります。
管理者は `enbu member admin` で別のメンバーにも管理者権限を付与できます。
権限を取り消す場合は `--revoke` を使います。

## 端末のアクセスを取り消す

管理者が `enbu member remove` を実行すると、現在のシークレットが残りのメンバー向けに再暗号化されます。
保存先へのアクセス権は、GHCR や S3 側でも確認し、不要になった権限を取り消してください。

## FAQ

### 読み取り専用のメンバーや、本番環境専用の権限は作れますか？

承認済みのメンバーには、ワークスペース内の全環境で閲覧と変更の権限があります。
閲覧者を分ける必要がある場合は、ワークスペースを分けてください。

### メンバーを削除したあと、API キーも交換する必要がありますか？

削除されたメンバーは、以前に取得した値を引き続き使えます。
アクセスを取り消すには、API キーやパスワードの発行元で値を更新し、新しい値を enbu に登録してください。

### 新しく参加した端末でも過去の履歴を読めますか？

承認時の再暗号化の対象は、各環境の現在のシークレットです。
過去のリビジョンの復号には、そのリビジョンを暗号化したときの受信者の鍵が必要です。
